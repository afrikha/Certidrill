# Certidrill content factory — Kubernetes / CNCF addendum

Read `factory/BRIEF.md` first, then `factory/BRIEF-EN-ONLY.md` (the CNCF exams are not offered in French: English only). Every rule there applies, **except** the points below, which replace the Microsoft-specific ones for the CNCF / Linux Foundation certifications (`content/kcna/`, `content/kcsa/`…).

1. **Vendor.** `certification.vendor: CNCF` (the exams are run by The Linux Foundation for the Cloud Native Computing Foundation). Never name Microsoft, Azure or AWS products as if they were part of Kubernetes; managed offerings (EKS, AKS, GKE) may appear only as neutral examples of "a managed Kubernetes service".
2. **Sources.** The curriculum PDF of the exam in `github.com/cncf/curriculum` (the version linked from the Linux Foundation certification page), the Linux Foundation certification page and candidate handbook/FAQ (`training.linuxfoundation.org`, `docs.linuxfoundation.org`), and the official documentation: `kubernetes.io/docs` (concepts, tasks, reference), `kubernetes.io/blog` for release notes, the CNCF glossary (`glossary.cncf.io`), the CNCF landscape and project pages (`cncf.io/projects`), and the official sites of CNCF projects (prometheus.io, helm.sh, opentelemetry.io, argo-cd.readthedocs.io, fluxcd.io, istio.io, linkerd.io, cilium.io, falco.org, open-policy-agent.github.io, kyverno.io, etcd.io, containerd.io, coredns.io, cert-manager.io…). Security frameworks for KCSA: the Kubernetes security docs (Pod Security Standards, RBAC, audit, secrets, network policies), CIS Kubernetes Benchmark (name only, no copied text), NIST SP 800-190, STRIDE, MITRE ATT&CK for containers, SLSA, the CNCF Cloud Native Security Whitepaper.
3. **Version.** State facts for the Kubernetes version of the current exam (see the certification page: e.g. "v1.37"). Removed or deprecated features (PodSecurityPolicy removed in 1.25, dockershim removed in 1.24, in-tree cloud providers, `kubectl run --generator`…) are only ever wrong answers or history. Verify feature stages (alpha/beta/GA) on kubernetes.io before stating them.
4. **Question types.** The exams are multiple choice with a single answer: `single`, 4 options. A few `multi` (Choose two/three) are allowed only if the exam handbook says multiple-answer questions exist; otherwise none. No case study, no series.
5. **Stem style.** Short and factual (KCNA: one concept, component, command or project to identify; KCSA: a threat, a control, a misconfiguration to spot). Manifests and commands are welcome: `yaml` for manifests, `bash` for `kubectl`/`helm` commands, `text` for command output. Keep them short (≤ 15 lines) and valid for the exam's Kubernetes version. Distractors are real Kubernetes objects, fields or projects that do something else.
6. **References.** 1–2 pages **that you fetched**, preferably `kubernetes.io/docs/...` or the project's official documentation; title = page title.
7. **Course code.** `bash`, `yaml`, `json`, `text` fences.
8. **Neutral names.** Namespaces, apps and companies are invented (`shop`, `payments`, `example.com`, `Example Corp`).
