## Doubts and unverified facts

- **Q9**: the v1beta4 reference changelog says the validity fields apply to certificates generated by `init`, `join`, `upgrade` and `certs`; I did not find an explicit sentence that `kubeadm certs renew --config FILE` reads `certificateValidityPeriod` from that file (the certs page only says renew does not rely on the `kubeadm-config` ConfigMap for attributes). The quiz relies on the changelog sentence.
- **Q10**: "a patch names its target by the base name, not the prefixed name" comes from the chapter and from kustomize's builtin transformer order (patches before namePrefix); kubernetes.io does not state it explicitly. Not run through a real `kustomize build`.
- **Q7**: an OCI reference with the tag (`oci://…/web-gateway:2.4.0`) instead of `--version` is rejected by the checks; helm.sh only documents `--version` (or a digest) for `helm install`, so I could not confirm that form is valid.
- **Tooling (factory/exercise.ts)**: `helm upgrade -i` is not parsed (no `i` → `install` mapping in `HELM_SHORT`, and `-i` then swallows the next word). So in Q7, `helm upgrade --install` passes but `helm upgrade -i …` fails, even though it is valid. Suggest adding `i: "install"` to `HELM_SHORT`.
- Helm history descriptions ("Install complete", "Upgrade complete", `Upgrade "edge" failed: …`) are typical Helm output; the helm.sh example uses other wording ("Initial install", "Upgraded successfully").
