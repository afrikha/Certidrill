## Points to review

- **NIC Teaming (LBFO) overview page** isn't in the Learn repo any more and its URL fails; LBFO facts come from the `New-NetLbfoTeam` reference (modes, algorithms, "different speeds not supported", guest example with `-AllowTeaming`) and from "Features removed or no longer developed" (Hyper-V switch can't bind to LBFO since Windows Server 2022). The old "guest teaming supports only switch independent / address hash" rule was left out (not verified).
- **SET default load-balancing algorithm**: written as `Dynamic` (default) per the `Set-VMSwitchTeam` reference; the Azure Local page recommends Hyper-V Port at 10 Gbps or more. Older memory says Hyper-V Port became the default; not verified, so the chapter follows the cmdlet page.
- **VHD maximum size**: 2,040 GB (Hyper-V scale limits page); the "features and terminology" page says 2 TB.
- **Live migration on Windows Server 2025**: CredSSP breaks because Credential Guard is on by default (Set up hosts for live migration article) — presented as an exam trap.
- **DHCP option precedence** ("the more specific level overrides the server value", reservation-level example) is standard behavior; Learn only shows that options exist at server, scope, policy and reservation level (`Set-DhcpServerv4OptionValue`). Option codes 003/006/015/044 are RFC 2132 values, only 006 seen in a Learn example.
- **DHCP server in Azure**: virtual-networks-faq now says a DHCP server in an Azure VM can serve on-premises clients through a relay (rate limit removed), with T1 renewals failing and T2 succeeding through the relay. Used in 42.
- **Zone resilience for Azure VMs** (preview, 2026-10-20) was left out of chapter 33 as preview.
- **Left out because not verified**: default DHCP lease duration (8 days found only for DHCPv6), Enterprise Admins requirement to authorize DHCP, Azure disk host caching defaults, DC DNS client loopback recommendations, DNSSEC default key parameters, autoscale "default count when metrics are missing".
