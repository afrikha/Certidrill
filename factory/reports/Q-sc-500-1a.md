## Deviations and doubts

- `consent-revoke-powershell`: the Learn sample removes application permissions with `Remove-MgServicePrincipalAppRoleAssignedTo -ServicePrincipalId $sp.Id` after listing them with `Get-MgServicePrincipalAppRoleAssignment`. The question uses `Remove-MgServicePrincipalAppRoleAssignment -ServicePrincipalId $spId` (the Graph operation that deletes an app role assignment granted to the service principal), and `...AssignedTo` is not offered as an option to avoid two defensible answers. Worth a check by a reviewer.
- `consent-workflow-reviewers`: Learn is inconsistent on who may approve Microsoft Graph application permissions (admin consent workflow page: only Global Administrators; grant admin consent page: Privileged Role Administrator too). The question only relies on what both pages agree on (Cloud Application Administrator cannot; a reviewer without a role can deny but not approve).
- `consent-user-setting`: the portal labels of the user consent options are only in a screenshot; the option names used are the policy descriptions on the page (`microsoft-user-default-low` = "Allow user consent for apps from verified publishers, for selected permissions", `microsoft-user-default-legacy` = "Allow user consent for apps"). "Do not allow user consent" is not quoted on the fetched page.
- `kv-resource-access`: options are the ARM/Bicep property names because the portal labels of the resource access check boxes could not be verified.
- `kv-bicep`: API version `2023-07-01` chosen and `enableRbacAuthorization` set explicitly, because the default of that property differs by API version (RBAC is the default from API 2026-02-01; the Bicep reference still says false when unspecified).
- `kv-name-recover` / `kv-retention-creation`: Managed HSM being more expensive than Premium, and Premium FIPS 140-3 Level 3, were not used as deciding facts.
- `pim-statements` s1: licensing statement follows the licensing page list (eligible/time-bound assignees, approvers, reviewers); permanent assignees are not tested.
- `am-tap-role`: Security Administrator as a distractor is not on the TAP page's role list (that list names Privileged Authentication Administrator, Authentication Administrator, Authentication Policy Administrator, Global Reader).
- `ca-policy-hotarea`: uses the new **Network** assignment labels ("Any network or location", "All trusted networks and locations").
- `app-account-types`: uses the current supported account type labels ("Single tenant only - <tenant>", "Multiple Entra ID tenants", "Any Entra ID Tenant + Personal Microsoft accounts", "Personal accounts only").
- **French**: role names, portal setting labels and enum values kept in English (Require approval to activate, Assignment required, Report-only...). « mode rapport uniquement », « attribution éligible / active », « identité managée affectée par le système / par l'utilisateur », « workflow de consentement administrateur », « réviseurs » taken from fr-fr pages; « passe d'accès temporaire », « clé d'accès (FIDO2) », « force d'authentification », « protection contre le vidage », « identité de charge de travail » not checked on a fr-fr page.
