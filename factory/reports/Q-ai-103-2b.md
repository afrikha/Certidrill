## Decisions and deviations

- App identity that only calls one agent: **Foundry Agent Consumer** at agent scope (CLI only; the portal assigns it at account scope only), per the RBAC page. The course chapter 21 still says Foundry User for "application identities"; the questions keep Foundry User only for apps that call models directly, which the RBAC page documents. Chapter 21 could mention Foundry Agent Consumer.
- `get_openai_client(agent_name=...)`: the AIProjectClient reference says it requires `allow_preview=True`, but the function-calling and Azure AI Search samples call it without that flag. No question tests the flag.
- Strict schema questions (`strict-optional`, `strict-schema-rules`) are framed as direct Responses API calls to gpt-4.1, not agents: the structured outputs page lists "Foundry Agents Service" as not supported, while the agent function-calling sample uses `strict=True`.
- `memory-user-scope` tests the frontend case (`{{$userId}}`, no header, fallback to tid/oid), distinct from `ai103-cs1b-guest-memory` (backend + `x-memory-user-id`).
