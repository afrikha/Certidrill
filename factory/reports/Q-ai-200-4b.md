## Decisions and doubts

- Like chapter 42, questions use `azure-monitor-opentelemetry` / `configure_azure_monitor()`. Learn (Sept 2026) now recommends the Microsoft OpenTelemetry Distro (`use_microsoft_opentelemetry`) for new apps. One ordering question (`ai200-4b-otlp-dual-export`) uses "don't initialize two distros" as a distractor.
- Default sampler: the README says rate-limited at 5 traces/s, but it also says `sampling_ratio` defaults to 1.0. `ai200-4b-sampling-defaults` s2 follows the rate-limited default, which the Learn sampling page also gives.
- Custom events (`microsoft.custom_event.name`): the Learn sample uses the Microsoft distro. I assumed the Azure Monitor distro behaves the same because both use the same exporter, but I didn't check this separately.
- `aiohttp` client and `celery` are treated as not bundled (README list). I know their community instrumentation packages exist, but I didn't fetch their pages.
- The statement "the span kind is set only by the `kind` argument" and "role name comes from resource attributes, not span attributes" (distractors in `ai200-4b-background-job-kind`, `ai200-4b-role-name-options`) come from OpenTelemetry semantics, not a Learn sentence.
- I left these out because I couldn't verify them: the numeric values of `SeverityLevel`, the exact separator in a cloud role name built from service.namespace and service.name, and the default success rule for HTTP 4xx requests with OpenTelemetry. The data model says 401 counts as success, but the add-modify page has a processor that overrides 4xx failures, so the two sources disagree.
- `distributed-trace-data` (W3C traceparent mapping) couldn't be fetched; the questions only rely on trace ID → `OperationId` (data model page) and on `traceparent` in the README Functions sample.
- French terms not checked against fr-fr pages: « étendue » (span), « cartographie d'application », « processeur d'étendues », « porteur (carrier) », « jauge asynchrone », « 95e centile ».
