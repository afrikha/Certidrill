## Doubts and choices
1. **Duplicates with other batches.** Other KCSA batches were written at the same time. After reading their stems I replaced five of my questions that tested the same decision as existing ones (3c-node-restriction-label, 3c-taint-plus-affinity / 1b-boundary-dedicated-nodes, 4b-kubelet-readonly-port, 4b-apiserver-kubelet-mitm, 1a-infra-port-10250). Close but kept, because the decision differs: `kcsa-2a-forbidden-stage` (which stage returned 403) vs `kcsa-3b-authz-no-opinion-deny` (outcome when no authorizer allows); `kcsa-2a-kubelet-flag-defaults-risk` (risk of flag defaults) vs `kcsa-4b-kubelet-anonymous-access` (the fix); `kcsa-2a-kubelet-config-gap` (set `readOnlyPort: 0` in a config) vs `kcsa-4b-kubelet-readonly-port` (identify port 10255). A reviewer may want to drop one of each pair.
2. **Encryption at rest provider strength.** The v1.37 encrypt-data page now rates `aescbc` as "Weak" and not recommended (padding oracle). Chapter 21 still shows an `aescbc` example as the first provider and the C-kcsa-1 table lists it among "secure values". My questions only ask for the `--encryption-provider-config` flag, but the chapter should be updated to prefer KMS v2 (or `secretbox`).
3. **Kubelet flags override the config file** (`kcsa-2a-kubelet-flag-overrides`), quoted from the kubelet reference ("Command-line flags override configuration from this file"). The kube-proxy question `kcsa-2b-proxy-config-overrides-flags` states the opposite for kube-proxy; both are consistent with their own component docs, but a reviewer should confirm the kube-proxy one.
4. **`--use-service-account-credentials` default**: the reference lists no default; questions only say what happens when it is set or not set (RBAC page wording).
5. **Taint filter disabled** (`kcsa-2a-taint-plugin-disabled`): the answer states only the scheduler effect (tainted nodes no longer filtered). Whether the kubelet would also reject such Pods for `NoSchedule` taints was not verified and is not claimed.
6. Not verified on a fetched page but stated: port 8080 as the old insecure API server port (removed), `kubectl cordon` not evicting Pods, ConfigMaps not meant for confidential data, kube-scheduler secure port 10259 not being on worker nodes. All low risk.
7. Removed `pods/binding` RBAC question: the subresource name could not be confirmed on a fetched page (Binding reference page failed to load).
