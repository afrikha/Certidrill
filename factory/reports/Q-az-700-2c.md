## Points to review

- **Reference titles** use the page H1 (bank convention), not the HTML title tag.
- **S2S VPN scale units**: Learn is inconsistent (gateway-settings: "1 scale unit = 500 Mbps ... two instances, each 500 Mbps"; FAQ: "10 scale units = 500 Mbps * 10 = 5 Gbps"). `az700-2c-vwan-vpn-scale-units` follows the FAQ aggregate rule (3 Gbps -> 6 units).
- **P2S scale units**: only the FAQ table rows (1, 10, 20, 100, 200 units) are used as options; intermediate values were not verified, so the question offers only those.
- **ExpressRoute scale units in a hub**: 2 Gbps per unit, 1 to 10 units (FAQ performance table).
- **Hub capacity**: 2 RIU = 3 Gbps / 2,000 VMs; RIU 3 = 3 Gbps / 3,000 VMs; RIU N (4-50) = N Gbps / N,000 VMs (hub-settings).
- **ASN reserved range** in `az700-2c-nva-bgp-asn` explanation written "65515 to 65520" (routing requirements page); the BGP peering page lists 65515, 65517-65520.
- **VPN over private peering** question uses a static local network gateway prefix (device without BGP) to make Azure prefer the tunnel; Learn describes the more-specific-prefix rule with BGP examples. Same longest-prefix logic, but not stated literally for static LNG prefixes.
- **French**: Virtual WAN rendered « réseau étendu virtuel » (as on fr-fr Learn), hub « hub virtuel », « unités d'échelle de passerelle », « unités d'infrastructure de routage », « intention de routage », « stratégies de routage », « connexions de branche ». Portal labels kept in English (Reset Router, Include ExpressRoute gateway, Gateway Private IPs, Use Azure Private IP Address, Hub routing preference values). An az-700 glossary would help.
