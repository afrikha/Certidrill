## Scope decisions and doubts

- Redundancy (LRS, ZRS, GRS, RA-GRS) is now part of the blob unit of the module: one drag-and-drop (`blob-dnd-redundancy`). Chapter 31 of the course does not cover it.
- The access tiers doc now lists a fifth option, "smart tier" (moves data between hot, cool and cold); the training unit still says four tiers. The ordering question says "the list contains four access tiers" instead of "the four access tiers". Chapter 31 does not mention smart tier.
- Table storage: the training unit says "semi-structured"; the docs say "structured NoSQL data" / "schemaless storage of structured data". No question asks to classify Table storage data as structured or semi-structured; explanations use the module's wording.
- Naming: questions use "Azure Data Lake Storage Gen2" like the training unit and chapter 31; the docs page now says "Azure Data Lake Storage".
- Beyond the training unit, from the docs only: lifecycle policies cannot rehydrate archived blobs; prorated early deletion charge; Azure File Sync agent on Windows Server and multi-server sync; a GPv2 account holds blobs, file shares, queues and tables; shares mounted concurrently from cloud and on-premises.
- Left out (unverified or too detailed for fundamentals): storage account capacity figures for Azure Files (256 TiB / 5 PiB), entity size and property limits of Table storage, Azure Files access tiers, tiering restricted to block blobs.
- Azure Files has little material in the study unit: a few facts are tested twice from different angles (NFS requirements, SSD/HDD, Azure File Sync), never with the same question and answer.
