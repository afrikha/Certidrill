## Decisions and doubts

- Scope: views, stored procedures and indexes (2.1.4) are not tested here; "indexing" appears once as a distractor.
- SELECT is classified as DML, as Learn does. The family question offers only DDL / DCL / DML (no DQL option).
- Facts beyond the training units, taken from the SQL docs: a primary key column never accepts NULL; DENY blocks a permission inherited from a role, REVOKE only removes a granted or denied permission; deleting a referenced row fails when no cascading action is defined (the stem states it). Used in the hard questions `rel-insert-outcome`, `sql-revoke-vs-deny`, `sql-drag-tasks`, `norm-delete-referenced`.
- Data types in code use T-SQL names (INT, VARCHAR, DECIMAL(10,2), DATE). Learn's own example writes `DECIMAL` without precision; `DECIMAL(10,2)` is used so that cents are really stored.
- SQL in stems is in `text` code fences (as in course chapter 21); dropdowns with `layout: code` have no `language` (SQL is not in the highlighter list).
- Table names follow course chapter 21 (Customer, Product, SalesOrder, LineItem) rather than Learn's `[Order]`, to avoid the reserved-word brackets.
- Thin objectives: the three Learn units are short, so some concepts (primary/foreign key, DDL/DCL/DML families, WHERE) are tested more than once, each time with a different decision, format and answer.
- French: fr-fr units say « applique l'intégrité des données », « clé composite », « intégrité référentielle », « langage de définition / contrôle / manipulation de données ». LineItem rows are called « ligne d'article (LineItem) » or « ligne de LineItem » to avoid « ligne de commande » (command line). Straight apostrophes per the brief.
- The hot area shows the column names as the first grid row (clickable cells), not as `header`, because only row cells can carry an `area`.
