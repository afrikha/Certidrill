## Chapter out of date or wrong against current Learn (I did not edit the chapter)

1. **o3 is retired.** The model retirement schedule (azure/foundry/openai/concepts/model-retirement-schedule) gives o3 2025-04-16 and o4-mini 2025-04-16 a retirement date of **2026-11-19**, replaced by gpt-5.6-sol / gpt-5.6-terra. The chapter uses `o3` as its example of 1 RPM per 1,000 TPM (section quotas-cost). The quota page still lists o3 in its ratio table. q10 gives the ratio through the response headers of a gpt-5-mini deployment and doesn't rely on the table.
2. **Unsupported tools with network injection.** The chapter says "browser automation, computer use and image generation". The current network isolation page lists **Fabric Data Agent, Logic Apps (under development), Computer Use and Image Generation** as unsupported, with partial support for Fabric IQ and Workflow Agents. It doesn't mention browser automation.
3. **Azure AI Search is now called "Foundry IQ (Azure AI Search)"** on several Learn pages (semantic ranking overview, the agent tool page "Connect a Foundry IQ (Azure AI Search) index to Foundry agents", the RBAC page "add Foundry to the Foundry IQ role assignments", the network page). Other Search pages still say "Azure AI Search" (hybrid scoring, indexer monitoring, OCR skill). The chapter and the quiz use "Azure AI Search", as the study guide does. The course may need to mention the new name.
4. **The Search tool with private networking** (missing from the chapter, worth a line): a basic agent setup doesn't support a search service with public access disabled behind a private endpoint, so you need the standard setup with network injection. Key-based authentication isn't supported with private networking: the connection must use the project's managed identity. q9 relies on this page, plus the chapter's "can't be added later" rule.
5. **Roles needed on an external search service.** The chapter only says "add Foundry to the role assignments". The tool page names **Search Index Data Contributor** and **Search Service Contributor**. It's inconsistent about which identity gets them: "the system-assigned managed identity of the Foundry account" in the prerequisites, "the project's managed identity" in setup and troubleshooting. q9 doesn't name the roles, and its option d follows the private-networking text ("project managed identity").
6. **Continuous evaluation status.** The new Agent Monitoring Dashboard page marks "Recurring evaluations (preview)", "Red team scans (preview)" and "Alerts (preview)" in its Monitor settings table, but not "Set up continuous evaluation" itself. The classic page ("Continuously evaluate your AI agents (preview) (classic)") is preview. A March 2026 Tech Community post says evaluations, monitoring and tracing are generally available. The chapter treats continuous evaluation, scheduled evaluation, scheduled red teaming and alerts as standard production practice, and several mock questions use continuous evaluation as the correct answer (ai103-1b-safety-evaluators-prod, ai103-1b-red-teaming, ai103-1b-observability-yn s1). **To be checked.** Because of this doubt, the quiz never uses them as an answer. q6 evaluates stored traces through cloud evaluation, which has no preview label.
7. **Preview agent evaluators.** The chapter lists intent resolution, task adherence and task completion among the agent evaluators. On the built-in evaluators reference, these three are **preview**, while Tool Call Accuracy, Tool Selection, Tool Input Accuracy, Tool Output Utilization and Tool Call Success have no preview label. Response Completeness and Groundedness Pro are preview too. The chapter's table "User questions changed → relevance and intent resolution scores" relies partly on a preview evaluator.
8. **Partial claims.** "Debug sessions" for enrichment failures: the indexer monitoring page doesn't mention them; I didn't verify them and didn't use them. The page names of the quota article now carry "(classic)".

## Doubts on the quiz

- **q8**: per the RBAC page, a storage account created outside Foundry needs Storage Blob Data Reader for the **Foundry resource's** managed identity. Some agent features with BYO storage (standard setup) may use the project identity instead. The stem follows the RBAC page's wording ("contoso-ai must use a new Blob Storage account"), and the project identity isn't offered for that slot. Foundry User is described as granting "reader access to Foundry project, Foundry resource", but the page's team mapping still assigns Reader on the resource to developers. The `dev` slot follows that mapping.
- **q2**: Learn recommends replacing `DefaultAzureCredential` with `ManagedIdentityCredential` once the app is deployed. The stem asks for the same code on the workstation and in Azure, which only `DefaultAzureCredential` meets. The explanation mentions the recommendation.
- **q4**: the indexer page says warnings for images or PDFs without text come from "indexers that use Foundry Tools", which is why the stem states that the skillset calls Foundry Tools.
- **q7**: the RRF bound (about 1/k per fused query, k around 60) and the descending sort by `@search.rerankerScore` were verified. The page doesn't state what `@search.score` holds when the semantic ranker is on, so the exhibit only shows plausible RRF values and no statement depends on it.
- **q10**: the RPM/TPM ratio is given by the headers in the stem. The quotas page doesn't give a per-deployment ratio for gpt-5-mini; its Tier 1 defaults (1,000 RPM / 1,000,000 TPM) match 1 per 1,000.
