## Chapter vs current Learn (fix in the chapter, not done here)

- **Copilot Studio real-time protection with Defender is changing.** "Protect AI agents in real time using Microsoft Defender" now says that the existing onboarding experience (the two-team procedure of the chapter: Defender URL, then the Power Platform admin center, then the App ID back in Defender) **retires on December 23, 2026**. Blocking settings set up that way don't migrate. Admins must disable the onboarding under **Settings > Security for AI > Get started > Copilot Studio**, then re-create and enable blocking rules under **Policies & rules > Real-time protection**. Automatic tenant-level onboarding is rolling out in public preview from November 22, 2026. After the retirement, agents with no enabled blocking rule run in audit mode, which raises alerts but doesn't block. The chapter's 3-step procedure and its Exam trap (nothing blocked until the App ID matches) will be out of date in a month. The mock questions about that flow should be checked too. Copilot Studio support in Defender real-time protection is labeled **(Preview)**, and it "currently evaluates tool invocations only".
- On the Defender page, real-time protection also covers Foundry agents (Preview) and Agent 365 Tooling Servers (WorkIQ, Custom MCP, GA). The chapter only mentions Copilot Studio.
- "Enable security for AI agents using Microsoft Defender": onboarding to Agent 365 now turns on security for AI agents automatically (the **Enable** toggle is on by default). Required role: **Security Administrator or higher**. For the Microsoft 365 connector, select at least Microsoft Entra ID Management events and Microsoft 365 activities. The chapter's "Global Administrator or Security Administrator" is consistent.
- Agent owners, sponsors and managers: an **agent user account** can have up to **5 sponsors of any group type**. The chapter's limits (100, of which at most 5 groups; no role-assignable groups) apply only to agent identities and blueprints. Assigned-membership *security* groups are not allowed as sponsors of agent identities or blueprints, and the chapter's wording suggests this but doesn't say it.
- Governing Agent Identities: agents that use regular service principals need a second assignment policy with **All Service principals**. The chapter doesn't say this. q6 s3 tests it, and the explanation gives the reason.
- Agent settings: Agent management rules also include **Reassign ownerless agents** (to the previous owner's manager), **Apply template**, **Install Microsoft (1P) agents** and **Reject agent publish requests older than N days**. **Sharing = No users** still allows direct sharing with specific people. The chapter only names "block ownerless agents without usage".
- Agent Registry: risk signals require an **E7 or A365** license. The chapter is consistent. Learn calls the page "Manage agent registry in Microsoft 365 admin center".

## Unverified facts and doubts

- The **DSPM for AI** license claim in the chapter ("Microsoft 365 E5 or Microsoft Purview Suite, E3 doesn't qualify") isn't on the considerations page I fetched. That page only mentions Copilot licenses and pay-as-you-go billing. No quiz question uses it.
- The chapter's "Applies to new sessions only" for real-time protection isn't on the Copilot Studio external threat detection page. Not used.
- q4: whether blocked actions produce alerts is unclear on Learn. The mock questions `sc500-3a-rtp-defender-rules` and `sc500-cs2a-realtime-protection` say near-real-time alerts appear only in audit mode, and the retirement note says audit mode "generates security alerts". For that reason q4 uses the Default (audit) rule and doesn't claim anything about alerts in block mode.
- q10 excludes approved agents **by custom security attribute**. "Target agents in Microsoft Entra Conditional Access policies" says that **Select agent identities** can select agents based on custom security attributes. The agent-id page says policies that target attributes apply to matching agents, including ones added later. No page explicitly shows attribute selection under **Exclude**, but the chapter teaches it ("or use custom security attributes").
- Most features of this chapter are preview (Copilot Studio external threat detection, AI Agents inventory, Agent risk (Preview), agent users (Preview)). The objectives can't be tested without them. Where possible, the correct answers rely on parts not labeled preview: DLP, User access, the Microsoft 365 connector, Lifecycle Workflows sponsor tasks, access packages, SAM features, and the Disable action. The Agent risk condition is never a correct answer.
- One fact not on a fetched page: in q1 option b, Detect risky AI usage is described as "detects and alerts". The considerations page says that Insider Risk policies "detect and alert but don't block", so this is consistent.

## Design notes

New decisions compared with the mock bank: DLP rather than DSPM to block pasting; User access for a pilot group; advanced hunting AI Agents queries for Copilot Studio blast radius; the missing Microsoft 365 connector; the Lifecycle Workflows sponsor transfer; agent self-request, expiration and the service principal policy; two registry entries for one agent; a four-tool SAM mapping (site access review, RCD, block download, authentication context); Disable rather than Confirm compromise when no agent-risk policy exists; token subjects with attribute exclusion, API keys and future agents.
