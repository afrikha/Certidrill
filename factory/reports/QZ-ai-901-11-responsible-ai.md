# QZ-ai-901-11-responsible-ai — doubts and notes

- **The mock bank saturates the chapter.** 89 bank questions cover 1.1.1–1.1.6 (`ai901-1a-*`, `ai901-1b-*`), and between them they test almost every practice the chapter lists. The quiz uses new scenarios and combinations. Some single facts still echo bank questions, though never as the same question with the same answer:
  - Q8: guardrails, PII detection, Key Vault and the model card appear in one drag-and-drop. The bank tests them separately.
  - Q10 m2: auditing access counts as privacy and security, as in an option of `ai901-1a-priv-two-actions-agent`.
  - Q4 m2: access limited to the care team.
- **Inclusiveness covers languages and technical skill (Q1).** Only "Responsible AI for agent design" (`agents/design-guidelines/responsible-ai`) says this: "language variation, and different levels of technical proficiency". The training unit "Identify guiding principles for responsible AI" doesn't mention it.
- **Traceability counts as accountability (Q5 s1, Q10 m3).** The chapter says so, but the guiding-principles unit doesn't name record keeping under accountability. It names governance, review boards and human oversight. The only support is "Artificial Intelligence overview" (compliance/assurance), which mentions "Metadata for auditing and compliance". Under privacy and security, the guiding-principles unit puts "auditing access and use" of customer data. Q10 uses this as its trap: logging who reads files is privacy, tracing which model version made a decision is accountability.
- **Removing sensitive columns doesn't make a model fair (Q9 s1).** No fetched Learn page talks about proxies or about dropping protected attributes. The answer rests on two things the unit does say: "bias can enter at every stage, from collection to modeling to operation", and you compare outcomes by group.
- **Chapter, Fairness > Evaluation bullet (could mislead).** The bullet says Foundry safety evaluators "scan the output … for bias and unfairness". The evaluator is "Hateful and unfairness" (`builtin.hate_unfairness`, 0–7 severity, pass/fail, reason). It measures hateful or unfair *content*. It doesn't check whether comparable people get comparable outcomes, which is the definition of fairness in the same chapter. Consider adding that nuance. Q3 only tests that evaluators measure and don't fix.
- **Chapter, Reliability > Generated content (missing detail).** Default guardrails apply to all Foundry Models "except transcription models". On text models they apply to prompts and completions at a Medium threshold, with user prompt attack (jailbreak) detection on. Document attack detection is off by default. This is correct as far as it goes; it is just not stated.
- **Preview evaluators.** Prohibited actions and Sensitive data leakage are preview, for agent targets only. They aren't used.
- **Content Credentials.** Images generated by Azure OpenAI image models carry Content Credentials (C2PA) automatically. This is on the *classic* page (`foundry-classic/openai/concepts/content-credentials`); the current default-policies page lists a "Content credentials" row for image generation. The chapter doesn't mention it, so Q7 sticks to a generic "mention that identifies the pictures as AI-generated".
- **Reference titles.** They use the page H1, as the AI-901 bank does (for example "Identify guiding principles for responsible AI"). The HTML titles differ slightly.
- **French.** Glossary terms follow the chapter and the bank: « garde-fous (filtres de contenu) », « évaluateurs de risque et de sécurité », « carte de modèle », « classements de modèles », « détection des PII d'Azure Language ». The evaluator name "Hateful and unfairness" is kept in English. No `undecided` glossary term was involved.
