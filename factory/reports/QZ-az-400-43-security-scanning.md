## Chapter or mock questions vs current Learn (fix there, not done here)

- **Agentless code scanning is preview.** `defender-for-cloud/devops-support` labels it "(Preview)" everywhere (code findings, IaC findings, SBOM). The chapter lists it without a preview label, as a source of code findings and as a prerequisite of the GHAS integration ("agentless code scanning on the connector"). The mock question `az400-4b-ghas-defender-setup` (ordering) makes "turn on agentless scanning for the connector" a required step of the correct answer, i.e. a preview feature in the answer. The deploy page (`github-advanced-security-deploy`) does say "Confirm agentless scanning is turned on for the GitHub connector", but its prerequisites list doesn't, and the linked page is marked preview. To review.
- **`dependabot.yml` and security updates**: the GitHub options reference now has `groups.<name>.applies-to: security-updates`, so `dependabot.yml` can shape security update pull requests (a group without `applies-to` still means version updates). The chapter's exam trap "`dependabot.yml` configures version updates only" and the Learn training unit ("The `groups` option applies only to version updates") are slightly out of date. Grouped security updates (a repository/organization setting, one PR per ecosystem, across directories) aren't in the chapter.
- **`open-pull-requests-limit`** applies to version updates only; security updates have a fixed limit of 10 open PRs (GitHub docs). Not in the chapter; q8 s2 deduces it from "dependabot.yml configures version updates".
- **Defender for Cloud CLI**: Learn documents `MicrosoftDefenderCLI@2` with `command`, `scanType`, `imageName` and `break: false`, but never explains `break`; the chapter's table ("fail the pipeline on critical findings") and its `break: true` example aren't backed by a Learn sentence. The CLI overview also says the Microsoft Container Security Scanner replaces Trivy image scanning; the chapter still lists Trivy (MSDO `containers`) for build-time image scanning.
- **GHAS for Azure DevOps** (`configure-github-advanced-security-features`): status checks `AdvancedSecurity/AllHighAndCritical` and `AdvancedSecurity/NewHighAndCritical`, "Enable all only enables existing repositories", default setup supports C#, C/C++, Java, JS/TS, Python, Ruby, Rust (Go and Swift need advanced setup), dependency scanning default setup ("Scan for vulnerable dependencies"), and Copilot Autofix for Azure DevOps is **public preview**. The chapter has none of the status checks or language limits.
- Learn "Dependabot alerts" training unit claims alerts are also generated when a pull request that introduces a vulnerable dependency is opened against the default branch. That is dependency review, not Dependabot alerts; the chapter is right not to say it.
- Chapter says the dependency graph is on by default for public repositories; not checked (the Learn unit only says Dependabot alerts aren't on by default).
- Confirmed as written: MSDO CredScan deprecated since Sept. 20, 2023 (replaced by GHAS for Azure DevOps); MSDO artifact `CodeAnalysisLogs`; MSDO `break` fails on high-severity results; PR annotations, code-to-cloud mapping (prerequisite: MSDO extension/action), attack path and Cloud Security Explorer need Defender CSPM; exposed-secret and OSS recommendations need GHAS and are in foundational CSPM; the Defender for Cloud CLI needs Defender CSPM; GHAS integration results take up to 24 hours (critical resources up to 12 hours); dependency review `fail-on-severity` values and "only one of allow-licenses / deny-licenses".
