## Sources and points of caution

- Every reference was fetched on learn.microsoft.com (en-us) on 2026-11-17. The `onelake-catalog-secure` and `create-streams-onelake-events` URLs failed to fetch; the Secure tab question (`dp600-2a-secure-tab`) is backed by the OneLake catalog overview page instead.
- Connection roles (`dp600-2a-conn-roles`): the Data source management page names User, User with resharing and Owner but does not detail each one. The mapping (Owner manages credentials and users) follows the role names and the course chapter.
- Connection types "On-premises / Virtual network / Cloud" in `dp600-2a-conn-gateway-auth` follow the Manage connections and gateways UI; the page I fetched only showed the Cloud path. Gateways are out of the profile's scope as an administration topic, so this question stays at "which connection type" level.
- `dp600-2a-trusted-access-steps`: the trusted workspace access page also mentions adding the workspace identity to the workspace with Contributor access; that step is not among the options, so the expected sequence (create identity, assign storage data role, create shortcut) is unaffected.
- `dp600-2a-copy-into-wsid`: the distractor credentials `IDENTITY = 'Shared Access Signature'` and `IDENTITY = 'Storage Account Key'` are real COPY INTO credential forms (they need a SECRET); I did not include `'Managed Identity'` because I could not confirm its support in Fabric.
- `dp600-2a-store-cosmos` relies on "Cosmos DB in Fabric" as listed in the Fabric data store decision guide (NoSQL, open table format in OneLake by default).
- `dp600-2a-mirror-prereqs`: the requirement for Member or Admin (Contributor lacks Reshare) comes from the Azure SQL Database mirroring tutorial.
- French: "copy job" is written « travail de copie (Copy job) », as in the course chapter (Learn FR uses both « travail » and « tâche »); "eventstream" is « flux d'événements ». UI labels (Explore, Govern, Secure, Endorsed items, All data streams, Microsoft sources, Fabric events, Trigger) stay in English.
- Overlap with case-study questions (`dp600-cs*`) was avoided where possible: S3 caching and Azure SQL mirroring choice are not repeated as standalone decisions; the mirroring questions here test prerequisites, tiers and costs instead.
