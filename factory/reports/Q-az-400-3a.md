## Deviations and points to review

- **Test taxonomy (az400-3a-test-levels).** The Learn page "Shift testing left with unit tests" defines L2 as functional tests that may need the assembly plus SQL or the file system, and L3 as tests against a testable service deployment. Course chapter `32-testing-strategy` describes L2 as tests against a lightweight deployment and L3 as tests against production. The question follows Learn; the course section should be checked.
- **CalVer (az400-3a-ver-calver).** I found no Learn page that describes calendar versioning. The question relies on the definition of the scheme, and its references are the Learn SemVer and artifact versioning units.
- **GitHub environments (az400-3a-gate-gh-env-rules, az400-3a-gate-gh-env-secrets, az400-3a-gate-toolchains).** The limits (up to six reviewers, one approval is enough, wait timer 1–43,200 minutes, Prevent self-review, environment secrets available only after approval) were checked on docs.github.com. The Learn reference ("Enforce governance with GitHub controls") covers only required reviewers and production secrets.
- **Unlist (az400-3a-feed-unlist).** Learn says that unlisting hides a version from search and keeps it in the feed. It doesn't say explicitly that a project can still restore the version by its exact number. That is standard NuGet behavior.
- **Exclusive lock (az400-3a-gate-exclusive-lock).** Learn says that with `runLatest` (the default) only the latest run acquires the lock. The explanation says the older waiting runs "do not deploy" and doesn't claim they are canceled.
- **View URL (az400-3a-feed-nugetconfig).** The current "Promote packages and manage feed views" page doesn't show the `feed@View` URL syntax. The syntax matches course chapter 31.
- **Action versions (az400-3a-gh-npm-publish).** The question uses `actions/checkout@v4` and `actions/setup-node@v4`, the versions in the Learn example. Course chapter 31 uses higher majors (`@v7`, `@v6`) that I could not verify because the shared WebFetch budget ran out once during the task.
