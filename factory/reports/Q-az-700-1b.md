## Facts checked on Learn, and points to watch

- The limits for routes per route table disagree between Learn pages: the UDR overview says 400 by default (1,000 with an AVNM routing configuration), and the subscription limits page says 1,000. No question uses this limit. The figure of 650 peerings per virtual network (limits page) isn't used either.
- Private DNS limits come from the subscription limits page: 1,000 links per zone, 100 links with autoregistration, 1 registration zone per virtual network.
- `az network vnet peering create`: in the CLI, `--allow-vnet-access` defaults to False (in the portal it defaults to selected). The dropdown question passes `true` explicitly.
- The CLI help for `--allow-forwarded-traffic` ("forwarded traffic from the VMs in the local virtual network ... in remote virtual network") reads the opposite way from the portal label ("Allow 'vnet' to receive forwarded traffic from the peered virtual network"). The questions follow the portal label and name the peering of the receiving network.
- The DNSSEC page doesn't say whether the feature is GA or in preview. The question only relies on how signing works (a DS record in the parent).
- AVNM connectivity page (Nov. 2026) lists **Enforce peering** and the `ConnectedGroupAddressOverlap` property. Neither is tested. Direct connectivity, Use hub as a gateway and Delete existing peerings are used.
- Assumed without a page that states it word for word: when a UDR and a BGP route have the same prefix, the effective routes show the BGP route as Invalid. The UDR overview states the precedence (UDR > BGP > system), but not the state label.
