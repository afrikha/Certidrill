## Deviations and doubts
- Type mix: single 21 (target 20) and dropdown 9 (target 10).
- The WebFetch budget ran out before I could fetch "Use Git with Lakeflow Jobs", so the questions don't use the
  task `source: GIT/WORKSPACE` field or notebook paths relative to the repository root. `git_source` keys and
  `git_provider` values come from the bundle resources page.
- `health.rules[].op: GREATER_THAN` (bundle YAML question) comes from the Jobs API. The Learn page only says "op (operator)".
- `{{job.start_time.iso_date}}` is assumed to give YYYY-MM-DD. Learn says "ISO date" and gives no sample value.
- The privileges page says "Service Principal User entitlement" in one place. The questions use "Service Principal
  User role", the usual Learn wording.
- The notifications page says "Tasks retry three times by default", which contradicts configure-task ("for most
  configurations, no retries"). The questions avoid default retry counts, except that classic compute doesn't retry.
- In the API, `continuous.task_retry_mode` defaults to NEVER, but the UI defaults to On failure. The questions
  only use the UI setting.
- Bundles are named "Declarative Automation Bundles (formerly Databricks Asset Bundles)", as in course chapter 43.
- I couldn't verify the branch naming patterns (feature/, bugfix/, users/) from the course on a fetched page, so no
  question uses them.
