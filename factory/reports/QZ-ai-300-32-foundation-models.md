## Chapter vs current Learn (to fix in the chapter, not done here)

- **Managed compute (Foundry projects).** Two Learn pages disagree. "Deploy open-source models with managed compute" still says preview, `GlobalManagedCompute` only, endpoint `https://<account>.services.ai.azure.com/openai/v1/`. "Deployment overview for Microsoft Foundry Models" doesn't label it preview. It gives data processing as "Global or Data Zone (US/EU)" and the endpoint as `<project endpoint>/managed-deployments/<deployment-name>/`. The chapter follows the first page (Global only, `/openai/v1/`). The overview also lists a third option, **Foundry Local on Azure Local** (preview), which the chapter doesn't mention. The quiz doesn't test managed compute in Foundry projects.
- **Role to call managed compute with Entra ID.** The managed compute page says Foundry User in one place and Azure AI User in another. The chapter says Foundry User. Not tested.
- **Deployment types.** Learn now says Global Standard supports Flex and Priority processing, and Data Zone Standard supports Priority processing. It also mentions "Instant access (preview)", which isn't a deployment type. None of this is in the chapter.
- **Data zones.** The deployment types page lists US, EU and APAC. "Provisioned throughput for Foundry Models" says Data Zone Provisioned stays "within a geographic zone (US or EU)". The chapter says US, EU or APAC for every data zone type.
- **PTU minimums.** The chapter says regional minimums are higher than global/data zone ones (25 or 50). Some current models break this rule: gpt-6-sol, gpt-6-luna and the gpt-5.6 family are 15 / 5 in Regional too.
- **Cached tokens.** For GPT-6 Astra and later models, cached tokens are weighted, not fully deducted. The chapter's formula `input TPM x (1 - cache rate)` holds only for earlier models. The quiz states this condition in the stem of q10.
- **Spillover.** Learn: spillover triggers on non-200 responses, not only on 429. It also triggers on 400 (gpt-4.1 requests of 128K tokens or more on PTU) and on 500/503. If both the deployment property and the `x-ms-spillover-deployment` header are set, the deployment property wins. Spilled requests show `IsSpillover = True` on the Azure OpenAI Requests metric. Spillover isn't supported for DeepSeek or Meta Llama models. The chapter only says that spillover reroutes "requests that would be rejected".
- **Model router.** The concept page doesn't confirm the chapter's "choose at least two" models for a subset. It doesn't give fallback rules either. Current facts not in the chapter: GA version `2025-11-18`; preview versions `2025-08-07` and `2025-05-19` retire on January 27, 2027; a routing fee is charged per million input tokens; images are accepted, but routing uses only the text.
- **Lifecycle.** GA models enter "Deprecated" (existing customers only) 12 months after launch. Anthropic, DeepSeek, Fireworks and Mistral AI models have a 12-month GA lifecycle instead of 18 months. Preview "not sooner than" dates are often extended, so the chapter's "Retirement dates can't be extended" holds for GA dates only.
- **Classic serverless example.** DeepSeek-R1 no longer appears in "Foundry Models sold by Azure", which lists DeepSeek-V3.2 and V4 models only. The classic page still uses DeepSeek-R1 as its example, and the chapter keeps it. Content filtering on classic serverless deployments is marked "(preview)" on that page.
- **Evaluation cost estimate.** "See Evaluation Results in Microsoft Foundry portal" says the estimated target inference cost is available only for Global Standard deployments. This matters for chapter 33 too.
- **In-place PTU migration.** A version change can be done in the Foundry portal, REST and the CLI. A change of model family can be done only with REST or the CLI. The chapter doesn't make this distinction.

## Doubts and design notes

- q7 assumes that a one-year reservation is cheaper than hourly billing, which Learn says ("discounted effective rate"). It doesn't compare a one-month and a one-year term, so none of the options is a one-month reservation.
- q4 and q6 depend on model availability by region and deployment type. The stems state it ("supports every deployment type listed below", "supports Global Standard deployments in the region") rather than naming a model.
- q10 uses gpt-5.4 (2026-03-05) values from the current sizing table: 2,400 input TPM per PTU, ratio 6, global and data zone 15 / 5, regional 50 / 50. They aren't in the chapter's table, so the stem gives them. The four wrong capacities match four calculation errors: no ratio (140), cache applied to output (205), regional increment (300), no cache (340).
- q9 uses the leaderboard (preview) only as a distractor. The leaderboard reference is the current page, "Compare models using the model leaderboard".
