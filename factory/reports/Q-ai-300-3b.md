## Deviations and doubts

- Azure ML now titles its serverless page "Deploy models as standard deployments"; questions keep the term "serverless" used by the CLI (`az ml serverless-endpoint`) and by the Foundry (classic) page.
- Regional Provisioned: the PTU concept page says data "stays in the deployment's specific Azure region", the deployment-types page says "within Azure geography". ai300-3b-ptu-cli-regional words the requirement as "not routed outside the Azure geography"; ai300-3b-ptu-type-per-workload uses "strict single-region data residency" (PTU page wording).
- The model catalog page says serverless deployments support "Keys and Microsoft Entra authentication", while the Foundry (classic) deployment-options table says key-less auth isn't supported for serverless. No question depends on it.
- The leaderboard page is inconsistent on the cost metric (actual vs estimated); ai300-3b-leaderboard-hotarea uses fictional candidates (Model-A..E) with a generic "Estimated cost" column.
- No Learn page shows the marketplace subscription YAML; ai300-3b-serverless-partner-order only names the `az ml marketplace-subscription create` command (exists, preview).
- `Standard_DS3_v2` for Phi-4 in ai300-3b-managed-sdk-deploy is copied from the Learn sample, though unrealistic for that model size.
- ai300-3b-mirror-new-version and ai300-3b-managed-version-rollout use online-endpoint safe rollout (close to 2.3.3) but framed on catalog model versions on managed compute.
- The Foundry course chapter 32-foundation-models didn't exist when the batch was written; alignment with it must be checked after it lands.
