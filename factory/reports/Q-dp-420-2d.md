## Doubts and deviations

- **Storage role for fleet analytics.** Learn (how-to-enable-fleet-analytics) says "Storage Blob Contributor", which isn't an Azure built-in role name. The course and these questions don't depend on it (no question tests the storage role name); the course uses Storage Blob Data Contributor.
- **Fleetspace JSON.** The Learn CLI sample puts `serviceTier` and `dataRegions` at the top level of the fleetspace properties, while its property table puts them under `throughputPoolConfiguration`. `dp420-2d-pool-fleetspace-cli` follows the CLI sample layout and only tests the values (tier, max, resource type), not the placement.
- **Key rotation column.** The schema reference names `LastDateAccountKeyRotated`, the enable page's sample query uses `LastDateAnyAccountKeyRotated`: not used in any question.
- **Pool max with 200,000 min.** `dp420-2d-pool-fleetspace-cli` assumes the default 1,000,000 RU/s "max pool RU/s" limit caps `maxThroughput` (10 x min would be 2,000,000).
- **Uneven dedicated RU/s per partition** in `dp420-2d-pool-partition-ceiling` is justified by a throughput redistribution across partitions (stated in the stem).
- **Control plane audit** (`dp420-2d-log-control-plane-audit`): based on Learn's "disable key-based metadata write access before auditing" recommendation; Learn doesn't explicitly say SDK key-based metadata operations are missing from ControlPlaneRequests, so the stem frames it as "audit as Microsoft recommends, through Azure Resource Manager".
