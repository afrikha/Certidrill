## Doubts and points for review

- gcpace-3a-hpa-kubectl-autoscale: the correct option uses `kubectl autoscale ... --cpu-percent=60`, as the GKE how-to page still does. The current kubectl reference on kubernetes.io lists `--cpu=60%` and no longer documents `--cpu-percent`, so the flag may be deprecated in recent kubectl. The other options are different commands, so the answer doesn't depend on which flag is used. A reviewer may want to switch to `--cpu=60%` once GKE docs do.
- gcpace-3a-k8s-statefulset-scale-down: the default PVC retention (`Retain` for whenScaled/whenDeleted) and reverse-ordinal scale-down are verified on kubernetes.io only. The GKE StatefulSet page that the question references doesn't state them.
- gcpace-3a-ar-pull-identity-facts: "user-provided service account → cloud-platform scope by default" comes from the Artifact Registry access control page and the gcloud `node-pools create --service-account` help. The statement about current versions not needing imagePullSecrets rests on the version note in the GKE integration page (needed only before 1.14.10-gke.22 / 1.15.9-gke.8).
- gcpace-3a-compute-viewer-role: uses the current basic role name "Reader (`roles/reader`)" as the IAM roles overview gives it. Compute Viewer's description ("read-only get/list of Compute Engine resources") isn't quoted from a fetched excerpt: the page was too long for the fetch window.
- gcpace-3a-nodepool-update-machine-type: `gcloud container node-pools update --machine-type` exists (recreates the nodes under the pool's upgrade strategy). Older study material says "create a new pool and migrate". The stem rules that out by requiring the same pool name.
- gcpace-3a-autopilot-balanced-class: the maximums used are General-purpose 30 vCPU/110 GiB, Scale-Out 54 vCPU/216 GiB (amd64) and Balanced 222 vCPU/851 GiB. The Spot Pods explanation says Spot changes pricing and eviction, not the compute class. I didn't find a sentence that says this explicitly.
