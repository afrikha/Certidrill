## Facts not verified on a fetched page (stable general knowledge, kept)
- Ownership chaining, dynamic SQL breaking the chain, `EXECUTE AS` / module signing.
- SNAPSHOT update conflict error 3960; `UPDLOCK, HOLDLOCK` and rowversion optimistic patterns; `NOLOCK` = READ UNCOMMITTED.
- DDM: `datetime()` function, `CONTROL` on the database sees unmasked data, `WHERE` inference.
- RLS block predicate operations list (`BEFORE UPDATE`, `BEFORE DELETE`), `@read_only = 1`, RLS applies to `db_owner`.
- Always Encrypted: `Column Encryption Setting=Enabled`, enclaves (range/LIKE, in-place encryption); column-level encryption key permissions.
- Execution plan signs table; DMV list (`sys.dm_db_resource_stats` 15 s / about 1 hour, `sys.dm_db_wait_stats`).
- Business Critical read replica with `ApplicationIntent=ReadOnly`.
- Azure SQL auditing: server policy always applies; enabling both creates two audits.
- Fabric SQL database supports only Microsoft Entra authentication.
- SQL projects: `RunSqlCodeAnalysis`, `dotnet new install Microsoft.Build.Sql.Templates`, SDK version 2.1.0 (from the NuGet search result), SQLCMD `/v:`.
- SqlPackage publish defaults `BlockOnPossibleDataLoss=True`, `DropObjectsNotInSource=False`; `DriftReport` (registered DB) is from the SqlPackage overview, `BlockWhenDriftDetected` left out.
- `SqlAzureDacpacDeployment@1` with `AuthenticationType: servicePrincipal` (to avoid a SQL password) — worth a check.
- GitHub `permissions: id-token: write`, CODEOWNERS last-match precedence, Azure DevOps checks (approvals, business hours, branch control).
- DAB: `runtime.host.mode: production`, `source.object/type`, provider spelled `EntraId` (Learn shows `EntraId`, `EntraID` and `AzureAD`).
