## Decisions and doubts

- **Transparent background**: Learn is inconsistent about which models support it ("GPT-image-1 only" in a code comment, and "GPT-image-1 and GPT-image-2" in a note). The question that uses it (`control-mapping`) is set on `gpt-image-1`.
- **`input_fidelity`**: Learn names no values. Options say "set to high" in prose only.
- **`images.edit` with `mask=` in the Python SDK** (`inpaint-code`): Learn shows the mask only as a multipart form field. The SDK parameter is standard, but no fetched page shows it.
- **Streaming event type** `image_generation.partial_image`, `partial_image_index` and `b64_json` are copied from the Learn sample. The `partial_images` maximum is 3 (Learn says "0 to 3" in one place and "1-3" in another).
- **Distractor facts that are standard but not on a fetched page**: `output_text` as an output content type, `response.output_text.delta`, `revised_prompt`, `create_variation`, and JSON mode (`json_object`) not enforcing a schema. Each is used only as a wrong option.
- **Image limits per request** conflict on Learn: Chat Completions vision page says 10, Responses page says 50. Only the Responses figure (50) is used, in `visual-rag`, and it is attributed to that API.
- **`contentFilter` HTTP status**: not verified, so it is not stated.
- **GPT-image-2.5 Sunburst/Flare** are not tested; `model-latency` lists only models whose access and sizes were verified, so Flare is not an option.
- **Overlap with case questions**: the mask questions (`inpaint-code`, `iterative-edits`) test mask dimensions and drift, not just transparent vs opaque (cs3a, sr1). The remix questions test the 24-hour expiry, chaining and prompt scope rather than the basic remix choice (cs4a).
