## Doubts and choices to review

- **Shared responsibility (11)**: the docs page contradicts itself (text: endpoints always the customer's; matrix: "Client devices = Shared" in SaaS, "Applications = Shared" in SaaS). The chapter follows the wording of the Learn training unit (provider manages the entire application stack in SaaS; data, identities and access, endpoints, configuration always the customer's) and gives no cell-by-cell matrix.
- **Zero Trust in French**: fr-fr pages use « Confiance nulle », « Confiance Zéro » and « confiance zéro » (objectives.yaml). Chapters use « Confiance Zéro (Zero Trust) » and the principle labels of the AZ-900 course (« Utiliser l'accès selon le moindre privilège »); the current fr-fr page says « Utiliser l'accès au privilège minimum ».
- **Workload identities (2.1.2)** verified: applications, service principals, managed identities. Learn now also teaches **agent identities** (Microsoft Entra Agent ID) in the same unit; covered in one paragraph of 21 and one row of 12, although the outline names only workload identities.
- **Authentication methods table (22)**: docs say Microsoft Authenticator push is not a primary method, the Learn unit says it is; the chapter merges Authenticator into one row (primary = passwordless sign-in, MFA = push). Hardware OATH tokens are still marked preview in the docs (not said in the chapter).
- **Left out because sources disagree or the fact is volatile**: whether administrators are enabled for SSPR by default; retirement of security questions for SSPR (Learn unit says March 2027); SSPR licensing; the 14-day MFA registration period (removed in 2024); device code flow blocking in security defaults.
- **Smart lockout**: defaults given (10 attempts, one minute) are those of Azure Public tenants; US Government differs (3).
- **Not fetched, written from stable knowledge**: in chapter 00, the one-line descriptions of products belonging to other chapters (Sentinel, Defender for Cloud, Purview DLP, labels, eDiscovery, audit, Service Trust Portal, secure score vs compliance score), "fundamentals certifications don't expire", "closed book"; in 23, the one-line definition of report-only mode; in 24, the usual pairing "sign-in risk -> MFA, user risk -> password change" (the ID Protection page lists both controls without pairing them).
- **Outside the outline, mentioned in at most one line or not at all**: Global Secure Access, Verified ID, Security Copilot integration, B2B direct connect, Azure Firewall Manager, Managed HSM, just-in-time VM access.
- **French product names** follow objectives.yaml (« Gouvernance Microsoft Entra ID », « Protection Microsoft Entra ID », « Pare-feu Azure », « Microsoft Defender pour le cloud »); role names, SKU names (DDoS Network Protection, DDoS IP Protection, Developer/Basic/Standard/Premium) and « Platform Credential for macOS » stay in English (fr-fr translates the latter inconsistently).
