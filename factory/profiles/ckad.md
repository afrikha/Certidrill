# CKAD exam profile (practice without a cluster)

- **Real exam** (Linux Foundation pages checked 2026-11-27): online, proctored through PSI Bridge, 2 hours, 15–20 performance-based tasks solved on the Linux command line, Kubernetes **v1.37**, pass at **66 %**, scored automatically (partial credit and task weights are not published). Each task names the host to `ssh` to and the namespace to use; `kubectl` with the `k` alias and Bash completion, `yq`, `curl`, `wget` are installed; `sudo -i` is allowed. Allowed documentation: kubernetes.io/docs, kubernetes.io/blog, helm.sh/docs. Offered in English, Japanese and Simplified Chinese: **English only** here. Domains: Application Design and Build 20 %, Application Deployment 20 %, Application Observability and Maintenance 15 %, Application Environment, Configuration and Security 25 %, Services and Networking 20 %.
- **What Certidrill can do**: no cluster. Practice tasks are `command` exercises (one command, checked on the objects kubectl would print in client dry-run, or on the parsed command for reads and operations) and `manifest` exercises (YAML written in an editor, checked field by field). Never present them as a realistic mock exam. Quizzes add `single`/`multi` questions on decisions and diagnostics.
- **Task style**: like the real tasks, short and operational, with every name given: namespace, object names, image with tag, ports, labels, file paths. "In namespace `shop`, create a Deployment `web` with image `nginx:1.27` and 3 replicas." One task = one command or one manifest. Hard tasks combine several fields (probes + resources + securityContext) or require the right field among similar ones.
- **Typical traps**: `--dry-run=client -o yaml` to generate, then edit; `command` vs `args` vs ENTRYPOINT/CMD; `restartPolicy` of Job (`Never`/`OnFailure`); CronJob `concurrencyPolicy`; native sidecar = init container with `restartPolicy: Always`; `emptyDir` `medium: Memory`; PVC `accessModes` and `storageClassName: ""`; Service `port` vs `targetPort` vs `nodePort`, selector mismatch → no endpoints; Ingress `pathType` (`Prefix`/`Exact`), `ingressClassName`; NetworkPolicy: `podSelector: {}` selects all, empty `ingress` denies, `from` items OR vs fields AND, DNS egress on port 53 UDP and TCP; `envFrom` vs `valueFrom`; Secret data is base64; `runAsNonRoot` vs `runAsUser`; capabilities at container level only; requests vs limits and quantity units (`500m`, `256Mi` vs `256M`); `rollout undo --to-revision`; Helm `upgrade --install`, `-n` with `--create-namespace`; Kustomize `apply -k` vs `kubectl kustomize`; removed apiVersions (`extensions/v1beta1`, `batch/v1beta1`, `policy/v1beta1`); `auth can-i --as system:serviceaccount:<ns>:<name>`.
- **Out of scope (CKA)**: kubeadm, etcd backup, node troubleshooting, cluster components, StorageClass provisioners internals, Gateway API.
- **Difficulty**: 20 % easy (one imperative command), 50 % medium (a manifest with 3–6 checked fields, or a command with several flags), 30 % hard (multi-field manifests, multi-document answers, debugging fixes).
- Every fact must match kubernetes.io for v1.37 (feature stages, defaults, field names); verify with WebFetch.
