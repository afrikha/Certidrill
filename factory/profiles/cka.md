# CKA exam profile (practice without a cluster)

- **Real exam** (Linux Foundation pages checked 2026-11-27): online, proctored through PSI Bridge, 2 hours, 15–20 performance-based tasks on the Linux command line, Kubernetes **v1.37**, pass at **66 %**, scored automatically (partial credit and task weights are not published). Each task names the host to `ssh` to; `sudo -i` is allowed; `kubectl` with the `k` alias and Bash completion. Allowed documentation: kubernetes.io/docs, kubernetes.io/blog, helm.sh/docs, gateway-api.sigs.k8s.io. Offered in English, Japanese and Simplified Chinese: **English only** here. Domains: Storage 10 %, Troubleshooting 30 %, Workloads & Scheduling 15 %, Cluster Architecture, Installation & Configuration 25 %, Services & Networking 20 %.
- **What Certidrill can do**: no cluster. `command` exercises (mode `object` for kubectl commands that create objects; mode `invocation` for kubeadm, etcdctl, etcdutl, crictl, systemctl, journalctl, helm and kubectl reads and operations) and `manifest` exercises (Kubernetes objects, and also YAML configuration files such as a kubeadm `ClusterConfiguration`, a `KubeletConfiguration`, a static Pod manifest of a control plane component, a CoreDNS ConfigMap). Troubleshooting is practised by giving the broken file or the symptoms (node conditions, events, logs, `crictl ps` output) in `body.files` or the stem and asking for the fixing command or the corrected manifest. Never present them as a realistic mock exam.
- **Task style**: short and operational, every name given (node, namespace, object names, paths such as `/etc/kubernetes/manifests/kube-apiserver.yaml`, `/var/lib/etcd`, certificate paths under `/etc/kubernetes/pki`, versions such as `v1.37.1`). One task = one command or one manifest.
- **Typical traps**: `etcdctl snapshot save` needs `--endpoints`, `--cacert`, `--cert`, `--key` (`ETCDCTL_API=3` is the default in etcd 3.4+); restore with `etcdutl snapshot restore --data-dir` then point the etcd static Pod's hostPath to the new directory; kubeadm upgrade order (kubeadm package → `upgrade plan` → `upgrade apply v1.37.x` on the first control plane, `upgrade node` on others → drain → kubelet/kubectl packages → `systemctl daemon-reload && systemctl restart kubelet` → uncordon), one minor version at a time; `kubectl drain --ignore-daemonsets --delete-emptydir-data`; static Pods are edited on disk, not with kubectl; kubelet config `/var/lib/kubelet/config.yaml`; `crictl` for containers when the API server is down; StorageClass `volumeBindingMode: WaitForFirstConsumer`, default class annotation `storageclass.kubernetes.io/is-default-class`; reclaim `Retain` leaves a `Released` volume; `ReadWriteOncePod`; taints `NoExecute` evict; `PriorityClass`; ClusterRole bound with a RoleBinding is namespaced; `auth can-i --as system:serviceaccount:ns:sa`; Service `targetPort` vs `port`; headless Service; DNS names `svc.ns.svc.cluster.local`; NetworkPolicy semantics; Gateway API `parentRefs`, `allowedRoutes`, `backendRefs` weights; Ingress `pathType`.
- **Out of scope (CKAD details)**: Dockerfiles and image builds, Helm chart authoring, application probes tuning beyond self-healing basics.
- **Difficulty**: 15 % easy, 50 % medium, 35 % hard (multi-step commands with several required flags, multi-document manifests, configuration files of control plane components).
- Every fact must match kubernetes.io, etcd.io and gateway-api.sigs.k8s.io for v1.37 (flags, paths, defaults, API versions: Gateway API resources use `gateway.networking.k8s.io/v1`); verify with WebFetch.
