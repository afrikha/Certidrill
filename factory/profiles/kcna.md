# KCNA exam profile

- **Format** (Linux Foundation pages checked 2026-11-23): online, proctored, 90 minutes, 60 multiple-choice questions, pass at 75 %, score emailed as a percentage within 24 hours. Two attempts per purchase (one retake). Offered in English, Japanese and Simplified Chinese (not French). Domains: Kubernetes Fundamentals 44 %, Container Orchestration 28 %, Cloud Native Application Delivery 16 %, Cloud Native Architecture 12 %. The mock exam scores all 60.
- **Kubernetes version**: not published for KCNA; write for **v1.37** (the version of the Linux Foundation Kubernetes exams and the latest minor on kubernetes.io). Removed features (PodSecurityPolicy, dockershim) are only wrong answers.
- **Types**: `single` only: 4 options, 1 correct. The handbook mentions no multiple-answer item: no `multi`, no case study, no series.
- **Stems**: beginner level, 1–2 sentences, one concept, component, command, field or project to identify: "Which component stores the cluster state?", "Which object runs one Pod on every node?". Short manifests (`yaml`), `kubectl` commands (`bash`) or output (`text`), at most 15 lines. Distractors are real objects, fields or projects that do something else.
- **Classic traps**: Pod vs ReplicaSet vs Deployment vs StatefulSet vs DaemonSet vs Job/CronJob; Service ClusterIP / NodePort / LoadBalancer / ExternalName / headless vs Ingress vs Gateway API; ConfigMap vs Secret (base64 is not encryption); control plane (kube-apiserver, etcd, kube-scheduler, kube-controller-manager, cloud-controller-manager) vs node components (kubelet, kube-proxy, container runtime); CRI vs CNI vs CSI vs OCI; requests (scheduling) vs limits (enforcement, OOMKilled, CPU throttling); HPA vs VPA vs Cluster Autoscaler vs KEDA; liveness (restart) vs readiness (removed from endpoints) vs startup probes; namespaced vs cluster-scoped objects, labels/selectors vs annotations; Role/RoleBinding vs ClusterRole/ClusterRoleBinding; PV vs PVC vs StorageClass, access modes, reclaim policies; taints/tolerations vs node affinity; `kubectl logs` vs `exec` vs `debug` vs `port-forward`; Helm vs Kustomize; GitOps pull (Argo CD, Flux) vs CI push; metrics vs logs vs traces (Prometheus, OpenTelemetry, Fluentd/Fluent Bit, Jaeger, Grafana); serverless and scale to zero (Knative); service mesh (Istio, Linkerd, mTLS); CNCF maturity Sandbox / Incubating / Graduated, TOC, TAGs, Kubernetes SIGs and KEPs; twelve-factor and personas.
- **Projects in scope**: Kubernetes and its SIG tools (kubectl, kubeadm, kind, minikube, Kustomize), containerd, CRI-O, runc, gVisor, Kata Containers, CoreDNS, etcd, Cilium, Istio, Linkerd, Helm, Argo CD, Flux, Prometheus, Grafana, OpenTelemetry, Jaeger, Fluentd, Fluent Bit, KEDA, Knative, OPA Gatekeeper, Kyverno, OpenCost. Verify a project's maturity level on cncf.io/projects before testing it.
- **Out of scope**: hands-on tasks and exact command output memorisation, cluster installation details, cloud-provider specifics (EKS, AKS, GKE only as "a managed Kubernetes service"), deep security hardening (KCSA), Helm templating internals.
- Difficulty: 40 % easy, 45 % medium, 15 % hard (hard = two similar objects or projects separated by one stated detail).
