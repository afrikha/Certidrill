# AI-103 exam profile

- **Exam created in 2026** (skills measured as of April 16, 2026). **Fetch every fact from learn.microsoft.com before writing it** (SDK classes, parameters, model names, limits); leave out what you cannot verify. Names as in the study guide: Microsoft Foundry, Foundry project, Foundry Tools, Azure Content Understanding, Azure Translator.
- 120 minutes, pass at 700/1000, Microsoft Learn available during the exam, "may have interactive components". Question count and formats are not published; the bank assumes 45–58 questions, one case study (4–6 questions), one "does the solution meet the goal" series of 3.
- **Level**: associate AI engineer who writes **Python**. Questions make you choose (model, Foundry service, retrieval method, deployment option, agent tool, evaluator, guardrail) and implement (complete a short Python snippet or JSON definition, order the steps of a RAG ingestion or an agent setup, read a trace or an evaluation result).
- **Stems**: 3–6 sentences, a fictional company, explicit constraints (cost, latency, keyless authentication, human approval, grounding quality), then "What should you use / do first / include?".
- **Formats**: single 35–45 %, drop-down 15–20 % (mostly code), multi 10–15 %, Yes/No statements 8–12 %, drag and drop 5–10 %, ordering 5–8 %, hot area rare.
- **Typical traps**: managed identity vs API keys; quota vs rate limit; vector vs hybrid vs semantic search; RAG vs tuning generation parameters; function calling vs knowledge tool vs memory; content filter vs evaluator vs tracing; single agent vs orchestrated multi-agent; Content Understanding analyzer vs multimodal model prompt; mask-based edit vs new generation.
- **Out of scope**: anything the study guide does not name (custom vision or language model training, bots, data science).
- Difficulty: 30 % easy, 50 % medium, 20 % hard (hard = two constraints combined or a code completion with close distractors).
