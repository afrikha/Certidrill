# SC-900 exam profile

- 45 minutes, about 35–45 questions, pass at 700/1000, closed book. No case study, no lab, no "does the solution meet the goal" series.
- **Level**: describe a concept or name the Microsoft product or feature that meets a need. No configuration steps, no licensing matrix, no PowerShell, no KQL, no policy JSON.
- **Stems are short**: one to three sentences. "Which Microsoft Entra feature ...?", "What can you use to ...?", three Yes/No statements, "Select the answer that correctly completes the sentence.", "Match each Microsoft Defender service to its description." (dragdrop).
- **Formats**: single (40–55 %), Yes/No statements (20–30 %), dropdown (10–15 %), multi "select two" (5–10 %), dragdrop (5–10 %); `ordering` and `hotarea` rare.
- **Classic traps**: authentication vs authorization; encryption vs hashing; Zero Trust principles; shared responsibility; Microsoft Entra roles vs Azure RBAC; Conditional Access vs MFA; Privileged Identity Management vs access reviews vs ID Protection; NSG vs Azure Firewall vs WAF vs DDoS Protection; Bastion vs Key Vault; CSPM vs cloud workload protection; SIEM vs SOAR; which Defender XDR service protects what; Defender portal vs Purview portal; compliance score vs secure score; sensitivity vs retention labels; DLP vs insider risk management; eDiscovery vs audit; Service Trust Portal content.
- **Current names**: Microsoft Entra ID (never Azure AD), Microsoft Entra ID Protection, Microsoft Defender XDR, Microsoft Purview portal. The October 21, 2026 outline says "workload identities" and "Microsoft Threat Intelligence": verify both on Microsoft Learn before writing.
- **Out of scope — no question**: anything absent from `objectives.yaml` (the outline lists no Azure Policy or resource locks, no Microsoft Intune, no Microsoft Priva, no Security Copilot objective).
- Difficulty: 40 % easy, 45 % medium, 15 % hard (two neighbouring products to tell apart or a subtle Yes/No statement, never obscure trivia).
