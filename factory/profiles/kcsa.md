# KCSA exam profile

- **Format** (Linux Foundation certification page and Multiple Choice Exams instructions/FAQ, checked 2026-11-23): online proctored, 90 minutes, 60 multiple-choice questions, pass at 75 % (score as a percentage). English only. One retake included; valid 2 years (passing CKS renews it). Domains: overview 14 %, components 22 %, fundamentals 22 %, threats 16 %, platform 16 %, compliance 10 %.
- **Version**: no curriculum version or Kubernetes version is published for KCSA. Write for **Kubernetes v1.37** and check feature stages on kubernetes.io. Removed or deprecated features are only wrong answers: PodSecurityPolicy (removed in v1.25), dockershim, KMS v1 (deprecated, disabled by default since v1.29), auto-generated Secret-based ServiceAccount tokens.
- **Level**: beginner. The candidate recognises a threat, a control, a component, a field or a project.
- **Types**: `single` only, 4 options (no source mentions multiple-answer items).
- **Stems**: 1–3 sentences, sometimes a short manifest (`yaml`), a `kubectl` command (`bash`) or its output (`text`), at most 15 lines. "Which control prevents ...?", "What is the risk of this configuration?". Distractors are real objects, fields, admission plugins or projects that do something else. Neutral names (`shop`, `payments`, Example Corp).
- **Classic traps**: the 4Cs (Cloud, Cluster, Container, Code; kubernetes.io now presents lifecycle phases instead, but the curriculum keeps the 4Cs); request order authentication → authorization → admission; RBAC least privilege (Role vs ClusterRole, RoleBinding to a ClusterRole, escalate/bind/impersonate, `create pods` as an escalation path), ServiceAccount bound tokens and `automountServiceAccountToken: false`; Pod Security Standards Privileged/Baseline/Restricted and Pod Security Admission modes enforce/audit/warn via namespace labels; securityContext (`runAsNonRoot`, `readOnlyRootFilesystem`, `allowPrivilegeEscalation`, drop capabilities, seccomp `RuntimeDefault`, AppArmor stable since v1.31, SELinux); user namespaces (`hostUsers: false`, stable since v1.36); NetworkPolicy is additive, needs an enforcing CNI, default deny with an empty `podSelector`; Secrets are base64, not encrypted, unless an EncryptionConfiguration (aescbc, aesgcm, secretbox, KMS v2) is set; etcd TLS and isolation; kubelet anonymous auth, Webhook authorization, read-only port, NodeRestriction; audit levels None/Metadata/Request/RequestResponse; supply chain (cosign/Sigstore signing, SBOM in SPDX/CycloneDX, scanning, SLSA, admission with OPA Gatekeeper or Kyverno, ValidatingAdmissionPolicy); Falco for runtime detection vs policy engines for admission; gVisor and Kata through RuntimeClass; service mesh mTLS and SPIFFE identities; STRIDE categories vs MITRE ATT&CK tactics; CIS Kubernetes Benchmark checked by kube-bench, NIST SP 800-190, PCI DSS; multi-tenancy (namespace vs cluster per tenant).
- **In scope (projects and tools)**: Kubernetes built-ins above; containerd, CRI-O, runc; Cilium, Calico; Istio, Linkerd; SPIFFE/SPIRE; cert-manager; Prometheus, OpenTelemetry, Fluentd/Fluent Bit; Falco; OPA Gatekeeper, Kyverno; Sigstore/cosign, in-toto; Harbor; kube-bench, Trivy, Kubescape.
- **Out of scope**: hands-on tasks (CKS level), managed-service specifics (EKS, AKS, GKE only as neutral examples), writing Rego or Falco rules, Windows nodes.
- Difficulty: 40 % easy, 45 % medium, 15 % hard.
