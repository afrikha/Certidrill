# DP-420 exam profile

- 100 minutes, pass at 700/1000, proctored. Since October 6, 2026: exam "Building AI Applications with Azure Cosmos DB", certification Azure Cosmos DB AI Developer **Associate** (formerly a specialty). Question count not published (bank target: 45–58, one case study of 4–6 questions, one Yes/No series of 3).
- **Skills list rewritten in 2026: fetch every fact from Microsoft Learn** (limits, defaults, SDK method names, policy syntax, preview/GA status). No longer listed: JavaScript stored procedures and triggers, Synapse Link, Azure Functions/Event Hubs integration, data movement tools, DevOps templates. New: Agent Kit, fleets (throughput, fleet analytics), dynamic data masking, partition failover, full-text, vector (DiskANN, sharded DiskANN) and hybrid search, RAG, agent memory stores, Fabric mirroring, Cosmos DB in Microsoft Fabric.
- **Scope**: Azure Cosmos DB (NoSQL API), applications in C# or Python.
- **Stems**: developer scenarios of 3–6 sentences with an access pattern, a volume or RU budget and one deciding constraint (lowest RU cost, latency, consistency guarantee, tenant isolation).
- **Hands-on level**: very high. SDK code to complete in C# or Python (client options, point read vs query, patch, transactional batch, bulk, ETag concurrency, change feed processor), queries, JSON indexing / vector / full-text policies, KQL on diagnostic logs. Favor `dropdown` with code; `single` for design trade-offs.
- **Typical traps**: partition key choice (cardinality, hot partitions, hierarchical vs synthetic); embed vs reference; point read vs query cost; consistency levels and their RU/latency impact; manual vs autoscale vs serverless throughput; change feed latest version vs all versions and deletes, processor vs pull model; backup modes; keys vs Microsoft Entra data-plane RBAC.
- **Not listed**: the other Cosmos DB APIs, model training.
- **Difficulty**: 30 % easy, 50 % medium, 20 % hard.
