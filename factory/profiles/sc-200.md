# SC-200 exam profile

- 100 minutes, 40–60 questions, pass at 700/1000. Microsoft Learn is reachable during the exam: questions test decisions, not recall. Plan one case study (4–6 questions) and one "does the solution meet the goal" series of 3.
- **Level**: an analyst working daily in the Microsoft Defender portal and Microsoft Sentinel. Very hands-on: which setting, role, connector, table, rule type or response action, and above all **KQL**.
- **Stems**: 3–6 sentences. A tenant (Defender XDR workloads, a Sentinel workspace, named device groups or tables), a requirement, often "minimize administrative effort" or "least privilege". Typical ends: "What should you configure?", "Which table should you query?", "Which operator should you use?".
- **Formats**: single choice (35–45 %), drop-down completion of a KQL query or a sentence (15–20 %), "select two" (10–15 %), Yes/No statements (5–10 %), drag and drop (5–10 %), ordering of steps (3–8 %), hot area (rare).
- **KQL**: `where`, `summarize`, `join` kinds, `extend`, `project`, `let`, `union`, `mv-expand`, `bin`, `ago`, `arg_max`; Defender XDR tables versus Sentinel tables.
- **Traps to cover**: automation rule vs playbook; scheduled vs NRT rule vs custom detection rule; Analytics vs Data lake vs XDR retention; Windows Security Events via AMA vs WEF; Syslog vs CEF; Sentinel roles vs playbook permissions; device group automation levels; live response vs investigation package; tuning vs suppression.
- **Out of scope**: deploying or licensing the Defender products, designing Purview or identity policies, the legacy Log Analytics agent (MMA).
- Difficulty: 30 % easy, 50 % medium, 20 % hard (hard = a KQL query to complete or two products combined).
- The October 21, 2026 guide contains very recent features (Sentinel data lake, KQL jobs, Sentinel Graph, hunting graphs, Sentinel MCP Server, case management, Security Copilot): fetch **every** fact from Microsoft Learn.
