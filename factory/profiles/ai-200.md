# AI-200 exam profile

- **Exam created in 2026** (Azure AI Cloud Developer Associate). The study guide has no "Skills measured as of" date (page dated 2026-04-15). **Fetch every fact from learn.microsoft.com before writing it** (SKUs, SDK calls, CLI commands, limits); leave out what you cannot verify. Guide names: Azure Cosmos DB for NoSQL, Azure Database for PostgreSQL, Azure Managed Redis.
- 120 minutes, pass at 700/1000, Microsoft Learn available during the exam, "may have interactive components". Question count and formats are not published; the bank assumes 45–58 questions, one case study (4–6 questions), one "does the solution meet the goal" series of 3.
- **Level**: associate back-end developer, **Python**. Hands-on: Python SDK code, `az` commands, Kubernetes and Container Apps YAML, SQL with pgvector, Cosmos DB queries and indexing policies, Redis commands, function triggers and bindings, KQL. Test what a developer codes and configures, not administration.
- **Stems**: 3–6 sentences, a fictional company with an AI workload, explicit constraints (latency, RU cost, scaling on events, retries, no secrets in code), then "Which code segment / command / setting?".
- **Formats**: single 35–45 %, drop-down 18–25 % (code block with two to four blanks), multi 10–15 %, Yes/No statements 5–10 %, drag and drop 5–10 %, ordering 5–8 %, hot area rare.
- **Typical traps**: App Service vs Container Apps vs AKS; revisions and KEDA scale rules; ACR Tasks vs local build; consistency level and indexing policy vs RU; vector index and distance choices; queue vs topic, dead-lettering, Service Bus vs Event Grid; trigger vs binding; Key Vault vs App Configuration; traces vs logs vs metrics.
- **Out of scope**: training models, Foundry agents and prompt design (AI-103), and any service the guide does not name.
- Difficulty: 30 % easy, 50 % medium, 20 % hard (hard = close code distractors or two constraints combined).
